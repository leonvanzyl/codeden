- **Project groups: related projects share skills and one memory.** Put projects in a group on the new **Project groups** page (the layers icon at the bottom of the sidebar, or the command palette), or from a project's **Settings** tab. A project is in at most one group. Skills you set on a group reach the agent sessions of every member project as ordinary skills in their worktree; a project's own skill of the same name wins. Each group has one shared memory that the project managers and agents of all its projects read and write (`read_group_memory`, `update_group_memory`), next to each project's own notes, which agents can now read and add to as well (agents only append; rewriting stays with the project manager and you, and secret-looking values are masked). Writes from several projects at once never lose one another, and you can view and edit the memory on the group's page. The orchestrator can list, create and change groups and assign projects (`list_groups`, `create_group`, `update_group`, `assign_project_group`). Deleting a group takes its projects out of it and deletes its memory. Group skills reach Claude Code and Codex sessions that run in a worktree or clone of their own.
