- **The factory looks after every pull request it opened until it merges or closes.** Before, the factory only watched a PR while its item was being verified. PRs of items that failed or were escalated were left alone, and rotted into merge conflicts while the default branch moved on. Now:
  - **Nothing is left to rot.** A PR waiting for you (auto-merge off, a protected area, checks that failed) is kept free of conflicts: its author rebases it, which isn't a revise round. When the author's session is gone, a fresh integrator session does it, briefed with the issue, the PR description and the review history. Merging or closing one on GitHub finishes its item. The factory never merges these itself.
  - **A merge queue.** With auto-merge on, approved PRs merge one at a time, oldest approved first. A PR that is behind the default branch is brought up to date on GitHub first (no agent needed), and merges once CI passes on the new head, so every merge is checked against the latest main. Only the PR next in line is updated, so CI doesn't run on every queued PR at once.
  - **Conflict fixes are re-checked, not re-reviewed.** After an agent resolves conflicts on an approved PR, the reviewer checks only the resolution (`git range-diff` of the old head against the new one) before it merges.
  - **Rebuild instead of fail.** A PR that still conflicts after three requests to rebase is redone from the latest default branch, for the same issue, keeping its analysis or reproduction. The old PR closes with a link to the new one. An item gets one rebuild.
  - **Hiccups don't strand work.** An item that failed for a reason outside its code goes back by itself on the next check after the cause is gone, at most three times. Its open PR is picked up again rather than redone. That covers a builder or reviewer session that died, CI that never started while GitHub Actions are on, and items that failed this way before this release. Such failures no longer count towards pausing the loop.
  - **Only what is truly stuck reaches you.** That is an item that already used its rebuild, a protected area, or CI that can never run (Actions off, no active workflow). It goes to your inbox and to the project manager. In a dark factory it arrives as a recorded decision, so the daily digest lists it.
  - The factory panel has a new **Pull requests** card: the merge queue in order, then every other PR the factory owns, each with its state (checking, waiting for CI, queued, updating, rebasing, rebuilding, waiting for you, stuck, merged).
