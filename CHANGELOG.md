# Changelog

All notable changes to CodeDen are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [semantic versioning](https://semver.org/).

## [Unreleased]

The notes for the next release are in [`changes/`](changes/README.md), one file per change. The release moves them into a version section here.

## [0.7.2] - 2026-11-14

### Added

- **`codeden runner-link`.** A new command that connects its stdin and stdout to the runner in `--home`. The server will start it inside a sandbox, through the sandbox's own command channel (for example `docker exec -i`), to reach a runner there. It needs no network port on either side, and a dropped link costs nothing: the runner keeps working, and the server opens a new link and catches up on everything it missed. Its output carries only protocol messages, with its log on stderr. It exits with code 3 when no runner is running there and 4 when the runner refuses it. With only the local runner nothing changes. This is the second step towards running agents in Docker containers and Upstash Boxes.
- **Workspaces for runners in a sandbox.** A runner that doesn't share the server's disk now clones the project into a folder it chooses, instead of being handed paths on the server's machine. Its files reach the server through the runner itself: the files panel, diffs, `share_to_chat`, `attach_evidence`, `generate_image` and browser screenshots never read its folder from the server's disk. Clones, fetches and pushes on such a runner get your GitHub token for that one git operation. The token is never stored in the sandbox, its git config, the runner's journal or any log. A session whose folder is gone now says so (`cwd_missing`) instead of failing with `spawn ENOENT`. With only the local runner, sessions work as before. This is the third step towards running agents in Docker containers and Upstash Boxes.

### Fixed

- **A `settings.json` with a typo no longer loses your settings.** A hand edit that broke the JSON (a trailing comma, a missing quote) made CodeDen start on default settings without a word, and the next change in Settings wrote the defaults over your file. CodeDen now keeps the broken file as `settings.json.invalid-<timestamp>` before it falls back to defaults, the same as for a file with invalid values. It also warns in the server log and puts a notice in the inbox with the reason and where the old file is. `codeden doctor` no longer resets a broken settings file itself.
- **The same protection covers the other files CodeDen writes back.** A damaged `usage-settings.json` (budgets and custom prices), `remote-access.json` (network access) or `image-usage.json` (today's image counts) is kept as a copy before anything saves over it, and you're told: in the inbox, or on the terminal when `codeden network` or `codeden password` runs while CodeDen is stopped. A damaged `remote-access.json` still leaves network access off until you set a password again. Its copy stays readable only by you, and the notice never shows the file's contents. Agents can't reach the copy either: like the file itself, it asks at every autonomy level, is off limits to read-only sessions, and can never be attached as evidence or shared to the chat.
- **Stopped factory work with an open pull request recovers by itself.** A failed item whose pull request gets new commits after its last review (a fix pushed late, or conflicts resolved), with CI green, now goes back to a fresh review of that pull request on its own, with no new build. It merges on approve as usual, and a request for changes gets one more revise round. This happens once per new head, at most three times per item, and never while the factory is paused. The review runs in a clean worktree on the pull request's head, so it sees every commit.
- **Retry re-reviews the open pull request.** Retrying a stopped item whose pull request is still open sends that pull request straight back to review with fresh revise rounds. It no longer redoes the reproduction or analysis or opens a second pull request. **Rebuild** still starts over.
- **Retry is easier to find, and the PM can use it.** Stopped items have a Retry button beside them in the factory panel's Recent column, not only on the item's page, where **Rebuild** sits next to it while the pull request is open. The PM can retry items too, with the new `factory_retry_item` tool (`rereview` or `rebuild`). Work let in from an untrusted author is retried only at your request.
- **Honest labels.** A failed item's pull request says "Stopped after N revise rounds; needs a re-review (Retry)" instead of "waiting for a person to merge it". That wording is now used only for escalated work.
- **The Factory view's "Needs you" lists only what waits on you, and says what to do.** Its cards were failed items that needed nothing (their issues already closed), while the header said "0 need you".
  - When an item's issue is closed on GitHub and the item failed without a pull request of its own, it settles by itself: **merged** ("Resolved by #n") when a merged pull request that links the issue closed it, otherwise **rejected** with how the issue was closed (a duplicate, not planned, completed).
  - One definition of "needs you" counts the lane, the header, the pixel scene and the daily digest's "Waiting on you", so they always agree. A failure the factory puts back by itself (a session that died, CI that never started) stays in its stage instead.
  - Every card says what's needed and has the button for it: **Review and merge PR #n** (escalations, and pull requests the factory doesn't merge itself), **Retry** for work that stopped with its pull request open, **Retry** or **Dismiss** for work that stopped without one, and **Answer** for an agent's question. Pull requests waiting for you and stuck ones now wait in the lane rather than in the merge queue, and an agent's question moves there from its stage. The card's side sheet has the same buttons.
  - **Dismiss** marks the item rejected with the reason (`POST /api/projects/:id/factory/items/:itemId/dismiss`).
- **The factory no longer picks a provider whose CLI is too old to run.** A Gemini CLI older than CodeDen supports now counts as unavailable, the same as one that isn't installed or signed in, so builders and the reviewer fallback skip it from the first try. If a session still can't open because the CLI is too old, the factory keeps new work off that provider and starts the reviewer elsewhere, without failing the review. Settings, the model pickers and the factory's Agents section say "Gemini CLI 0.36.0 is too old (needs 0.68.0+)" with the update command.
- **CodeDen's Codex sessions no longer fill the Codex app's recents.** The Codex apps list every Codex conversation on your machine as yours, so factory reviewers, builders, PMs and other CodeDen sessions crowded out your own chats. A CodeDen conversation is now visible in the Codex app only while one of its turns is running; the rest of the time it is under the app's **Archived** conversations. CodeDen unarchives it just before the next turn, a resume or a fork, so nothing is lost, and archives a fork's copy as it is made. A turn that fails to start, an interrupted turn or a Codex process that crashes doesn't leave one listed either, and when CodeDen starts after being killed mid-turn, it archives what was left. Your own conversations are never touched.
- **Hide the ones from before.** **Settings → Providers → Provider apps → Hide CodeDen's sessions from the Codex app** lists the conversations CodeDen started that the Codex app still shows, found by CodeDen's own record of them rather than by their titles. It archives them once you confirm. They are archived, not deleted, and CodeDen can still resume them.
- **Claude Code sessions stay out of `/resume` when CodeDen runs from a Claude Code terminal.** CodeDen now always labels its Claude Code sessions as SDK sessions, which Claude Code's own `/resume` leaves out, instead of inheriting the terminal's label.

### Security

- **The files panel never opens CodeDen's own credential files.** If a session's folder contains CodeDen's data folder (a project at your home folder, say), the install token, the runner lock and the `.invalid-*` copies kept of damaged ones are refused, as `share_to_chat` and `attach_evidence` already did.

## [0.7.1] - 2026-11-14

### Added

- **Factory view.** A calm, full-screen view of a software or dark factory, made to stay open on a second screen. Open it with **Factory view** on the project page or the factory panel, from the command palette, or at `/projects/<id>/factory/view`.
  - The pipeline runs left to right as stages (Intake, Identify type, Building, Reviewing, Merge queue, Merged). Every item is a card showing what its agent is doing now, how long it has been in its step, its pull request's state and merge checks, and whether it's running, waiting, needs you or failed.
  - Cards move live. Clicking one shows its steps, pull request, checks and sessions in a side sheet.
  - Escalated and failed work gets its own **Needs you** lane (however old, while it still waits), stuck pull requests are marked in the merge queue, and the header counts what waits on you.
  - One row of figures shows spend against the budget, merges today, agents working, open PRs, failures and reverts today, and the median time from issue to merge over 7 days.
  - A quick PM chat sits beside it, and the header has the kill switch, **Check now** and **Run scout now**.
  - **Full screen** fills the screen (F11 in the desktop app). On tablets and phones the stages stack and the chat opens as a bottom sheet.
- **Open PR from the session's Diff panel.** In a GitHub project, the git bar has an **Open PR** button that asks the agent to open a pull request for the session's work. The agent commits what's left, pushes and writes the description. If a turn is running, the request waits in the queue behind it. A successful push offers the same next step, and the Issue / PR tab offers it while nothing is linked. Once the PR is open, the git bar shows **PR #N** and opens it. The button appears in sessions you started on their own branch; sessions a PM, automation or the factory started still open their own PRs.
- **Cursor as a provider.** Sessions can run on the Cursor CLI with your own Cursor login and the models your plan includes. CodeDen drives the CLI's Agent Client Protocol server (`agent acp`), so transcripts, approvals at every permission level, plan mode, questions, todos, interrupt and resume after a restart work as they do for the other providers. Setup and `codeden doctor` detect the CLI, offer **Sign in** (`agent login`), and ask for `agent update` when the installed CLI has no ACP server. Check your Cursor plan's terms before using it for unattended work such as the software factory.
- **Pixel mode in the Factory view.** A toggle in the header swaps the board for a small pixel-art factory floor that works along with your factory. Tickets pile up at the door, a worker hammers at a bench for each build, reviewers inspect crates, the merge queue rides a conveyor to the shipping door, and failed or escalated work smokes on broken machines under a "needs you" flag. In a dark factory the scout walks the floor with a magnifying glass. A gauge shows spend against the budget, a counter board shows today's merges, and the lights dim when the loop is stopped.
  - Hover anything to see its issue, and click it to open the same side sheet as on the board. A line under the scene says what it shows, for screen readers.
  - It's off by default and remembered per browser. It's light (one small canvas at about 12 frames a second, paused while the tab is hidden), shows a still frame with reduced motion, and isn't offered on phones.
- **Cursor subagents and image generation.** When a Cursor session delegates work to a subagent, the transcript shows a subagent card you can open to follow its own thread: what it was asked, the commands it ran, the files it read and edited, and its answer. The card shows its live status, then its result, tool calls and duration. Approvals a subagent needs are asked in its thread and also show in the session and your inbox, decided by the session's permission level like any other. Needs Cursor CLI 2026.09.15 or later; older CLIs show a card with the task and its result once it is done. Images Cursor generates now appear inline in the transcript and are saved with the session, as Codex's do.
- **Turn off `CI=true` for a project's agents.** **Settings → General → Agent environment** has a switch per project, on by default. Turn it off when a project's tools misbehave under CI (Playwright not reusing your running dev server, Yarn refusing to update the lockfile, builds failing on warnings): agent sessions opened after that run without `CI` added. pnpm may then ask again before reinstalling `node_modules`, so set `confirmModulesPurge: false` in that project's `pnpm-workspace.yaml`. The orchestrator can change it too (`update_project`).
- **Gemini CLI as a provider.** Sessions can run on Gemini CLI (0.68 or newer) with the login you chose in it: Google, a Gemini API key or Vertex AI. CodeDen drives its Agent Client Protocol server (`gemini --acp`) through the same client as Cursor, so transcripts, approvals at every permission level (CodeDen's own tools recognised by the MCP server Gemini CLI names), plan mode with a **Plan ready** card for its plan, token usage, interrupt and resume after a restart work as they do for the other providers. Sessions run in Gemini CLI's `default` mode even when yours defaults to YOLO, and CodeDen never signs it in itself, so your chosen login method is never changed. Setup and `codeden doctor` detect the CLI, read its login from its own settings without touching credentials, and offer **Sign in** (`gemini`). Questions, its subagents and steering are not wired up yet. Check your plan's terms before using it for unattended work such as the software factory.
- **Hand a session off to another provider.** When one provider hits its usage limit, or you want a second opinion or another model's strengths, choose **Hand off…** in the session's ⋯ menu or the command palette, or click another provider's tile in the session's model picker ("Continue in a new … session"). Pick the provider and model, and optionally say what to do next. The new session gets the same code as a fork (a new branch with the original's uncommitted changes) and, instead of the conversation, a brief CodeDen writes from the original's transcript: the task, later requests, where the work got to, open todos, the files edited and your note. It works on every provider, including ones that can't fork, and the original session is unchanged. The utility model writes the "where it got to" summary; switch it off in Settings > Utility model > Handoff summaries.

### Changed

- **Adding a project leads straight into a first session.** Finishing first-run setup with a project, or adding one from the sidebar, now opens the project's New session view, ready to type the first task, instead of an empty project page. A project page with no active sessions now explains what a session is and offers **Start a session**.
- **The factory finishes open work before it starts more.** A free agent now goes to a review first (of a pull request whose CI passed), then to a rebase or revise round, then to a review of a pull request whose CI is still running, then to a build (one carrying on after a failure before a new one from the queue), and to the scout last. Work in progress is never interrupted. Revise rounds and rebase requests now wait for a free agent instead of going past **Agents at once**.
- **PRs open at most.** A new work-in-progress limit in the factory settings (`maxOpenPrs`, by default the same as **Agents at once**). With that many factory pull requests open, waiting for you to merge them included, no new build starts from the queue and the dark factory's scout files nothing until one merges or closes (a scout round already running keeps its findings and files them then). A fix for failing checks on the default branch still starts. The factory panel and the Factory view show **Finishing open work (2 of 2 PRs open)** while the limit holds work back. With auto-merge off, raise it if you merge in batches.
- **Queued work that touches the same files as an open pull request waits its turn.** When an issue names files an open factory pull request changes, other queued work starts first ("Deferred: likely overlaps open PR #12"); it still starts when nothing else is waiting.

### Fixed

- **Stop also stops a Codex sub-agent that starts late, when Codex is slow to confirm.** If Codex confirmed the stop after CodeDen had already closed the turn, an agent that was just being spawned could start and keep running. It is now stopped as well, and its card stays cancelled.
- **The runner's start-up error always says how it exited.** When the runner process ended during start-up on a busy machine, the error could leave out its exit code; it now waits a moment for it.
- **"Are you sure?" dialogs in the session browser wait for an answer instead of closing at once.** A page's `alert`, `confirm` or `prompt` used to be dismissed the moment it opened, so a "Delete this item?" confirm returned Cancel whether you or the agent clicked the button, and the action silently didn't happen. Now the page pauses and the browser panel shows the dialog over it with **OK** and **Cancel** (and a text field for a prompt), on both the streamed browser and the desktop app's native one. Agents see the dialog in the result of the click that opened it and in `browser_snapshot`, and answer it with the new `browser_dialog` tool. A dialog nobody answers is dismissed after 2 minutes, and the panel says so. When you or an agent navigate away, a page's "Leave site?" no longer holds up the navigation.
- **First-run setup on phones.** A failed check shows its whole reason, such as "Installed (0.58.0) but not signed in", instead of a few letters, and its copy-command chip and fix button move to their own line below it. The Claude Code support row's description wraps too.
- **Voice & notifications step.** Screen readers now announce the **Read final messages aloud** switch by name. When notifications are blocked, the row says how to allow them again (in the site settings, or in the system settings for the desktop app) and has a **Check again** button. On a page served over plain http, such as a phone on your network, it explains that browsers only allow notifications on secure pages.
- **Wait and Join on the "Already running" card keep to the work that conflicted.** If the New session draft had no typed work key and you edited its text after the card appeared, the edited text produced a different work key, so Wait, Join and Force started a new session alongside the running work. They now start your edited draft under the work key that conflicted, so Wait queues behind that work and Join sends the draft to it. If you change the typed work key, the card asks you to send the draft again so the new key is checked for running work.
- **Sending a conflicting draft again always closes the conflict it replaces.** The earlier conflict was looked up among the 500 most recent conflict records only, so an older one, together with its inbox item, stayed open next to the new one. It is now found by its id, however old it is.
- **A runner removed or shut down while it is still connecting stays disconnected.** Removing a runner or closing the server while CodeDen was still finding or connecting to it could finish the connection anyway: the runner was recorded as connected again after it had been deleted, and it kept answering commands after the server had closed. Removing a runner or closing the server now cancels the connection and waits for it to end, and a connection that completes too late is closed without being recorded.
- **"Runner not connected" errors give the runner's id.** When a session's runner is not connected, the error now gives the runner's id along with its name and backend, so you can tell which runner the session lost, as the error for a deleted runner already did.
- **Agents no longer inherit CodeDen's own settings.** Agents of every provider, terminals and setup scripts used to get CodeDen's internal `CODEDEN_*` variables, such as its data folder (`CODEDEN_HOME`) and, in the desktop app, its installer (`CODEDEN_DEPS_INSTALLER`). A project that reads them, CodeDen's own repository included, then pointed at your real CodeDen data folder and the npm registry from inside a session. These variables now stay inside CodeDen, and the rest of your environment is passed through as before.
- **Claude's subscription limits show how much is used.** The Usage page now reads the 5-hour, weekly and per-model weekly windows of a Claude subscription login with their percentages when a session starts and after each turn, so the Weekly card no longer reads "— used" next to an empty bar. When Claude has reported only a window's status, the card says "Within limit", "Close to the limit" or "Limit reached" with the reset time and no bar. A newer status-only report no longer erases the last known percentage, which keeps its own "as of" time until the window resets.
- **Agents no longer hang on install prompts.** When pnpm had to rebuild `node_modules` (after a rebase, a lockfile change or an interrupted install), it asked "The modules directory will be removed and reinstalled from scratch. Proceed?", which nothing can answer from an agent's shell, so the install waited forever. Agent sessions now run with `CI=true`, so pnpm reinstalls without asking and other tools skip their prompts too. If you set `CI` yourself (`CI=false` to opt out everywhere), your value is kept; you can also turn it off for one project in **Settings → General → Agent environment**. Your terminals are unchanged. Inside agent sessions, your project's own tools now behave as they do in CI:
  - **Playwright:** configs with `reuseExistingServer: !process.env.CI` start their own dev server and fail when yours is already running; `forbidOnly: !!process.env.CI` fails the run on a `test.only`; `retries: process.env.CI ? 2 : 0` quietly retries failing tests.
  - **Installs:** a plain `pnpm install` won't update the lockfile, and Yarn Berry turns on `enableImmutableInstalls`, so `yarn install` fails after an agent edits `package.json` instead of updating `yarn.lock`.
  - **Builds and tests:** Create React App and similar builds treat warnings as errors, test runners don't write new snapshots, and other tools switch to CI reporters or skip interactive setup.
- **A factory reviewer's broken local install no longer fails a pull request.** A reviewer whose own checkout couldn't run the tests (dependencies missing or corrupted after an interrupted install, timeouts under load) could request changes for that alone, which used up a revise round and could fail an item whose code was right and whose CI was green. Reviewers are now told that CI on the pull request's head is the authority for the full test suite, to reinstall a broken install non-interactively before testing, and never to request changes only because local checks couldn't run. A request for changes marked `blockers: "environment"` never reaches the author: the reviewer gets the CI result and reviews again. If its environment stops it a second time, the item fails as an infrastructure failure, which the factory recovers by itself without using a revise round, and the next reviewer works in a clean worktree on the PR's head.
- **The orchestrator and PMs tell you times in your own timezone.** Their status digest used to carry only a UTC time, and nothing told them your timezone. So a PM at UTC+2 said "I'll check again at 20:02" when it meant 22:02 your time. The digest now also carries your timezone and local time, and their instructions say to quote times in your local time. Wake-ups they schedule show the local time next to UTC. The timezone is the one usage reports use: the usage settings' timezone, else your computer's.
- **Agents keep CodeDen's tools after a restart or upgrade.** A session reopened right after a restart could have every CodeDen MCP call rejected ("Authentication required" or a 401). This happened when a message from a PM or the factory reopened it while CodeDen was still resuming the sessions the restart cut off. The second reopen revoked the token the running agent held, so a factory reviewer could finish its review and still not record its verdict. A reopen now retires a session's earlier tokens only once the new agent process is running, and a session that a message is already reopening is not opened a second time. Stopped sessions' tokens stay revoked.
- **An expired sign-in on OpenCode no longer fails factory reviews over and over.** When OpenCode's model login had expired (for example an `openai/*` model while the OpenAI login was out of date), the turn failed with `Request failed: 401`. CodeDen counted that as an ordinary failure, so every replacement reviewer started on OpenCode again until the item failed. A 401 or 403 that OpenCode puts only in its error message now counts as a sign-in problem, as one in the status field already did. The reviewer then restarts on another available provider straight away, without using a revise round or one of the reviewer's restarts, and factory work stays off OpenCode for 30 minutes before it is tried again.
- **An MCP server's form no longer turns a typo into a refusal.** Number fields on a Codex MCP form are checked as you type, with a note saying what fits, and common ways of writing numbers are understood ("1,000" is 1000). An answer that still doesn't fit is sent back to you with what the field takes, and the form stays open, instead of the server quietly getting a decline while the card showed your answer. A form you dismissed or declined now says so in the transcript instead of looking answered.
- **The project manager no longer fills in MCP servers' forms.** Like approvals, an MCP server's form stays with you: `answer_question` refuses it instead of copying the PM's sentence into every field, and the PM's update says the form is waiting for you.
- **A pull request GitHub refuses to merge no longer blocks the merge queue.** When GitHub refuses to merge or update the pull request at the head of the queue (branch protection, a required check or review), the factory tries again on the next check, and after three refusals on the same commit it takes the pull request out of the queue as stuck, with what GitHub said, tells you once in the inbox and the PM, and merges the next one in line. A new commit on the pull request starts the count afresh. GitHub being down or rate-limited never counts: the factory just tries again.
- **A signed-out or rate-limited provider no longer freezes the factory.** Pull requests of work waiting for its provider to sign in again or for its usage limit to reset no longer count toward **PRs open at most**, so new work carries on with the other providers. The factory panel and the Factory view say which pull requests wait on what ("1 PR waits on Codex (not signed in) and doesn't count"), and the PM hears once when work has waited for five minutes.
- **PRs open at most is never overshot.** Builds that haven't opened their pull request yet now take room under the limit, so one check no longer starts a build for every free agent.
- **Stop works while Cursor or Gemini CLI is still starting.** If the agent CLI had to start again for a message (after it quit or crashed), pressing Stop before it was up did nothing: the message was sent anyway and the agent went to work. The turn now ends as stopped at once, the message is never sent, and the agent keeps starting so your next message is quick.
- **A factory reviewer that takes over from another one is reminded to submit its verdict before its review can fail.** When a reviewer session died, was stopped or hit a provider problem (a usage limit, sign-in) after it had been reminded, the fresh reviewer that replaced it was never reminded itself. If it ended a turn without a verdict, the review failed after the grace period and cost the pull request a revise round. Each new reviewer now gets its own reminder first, and its review fails only if it ends without a verdict again.
- **A session on another provider starts on that provider's default model.** The model and effort set for a role in Settings > Providers now apply only to sessions on that role's provider. Before, a factory reviewer on Codex (reviewing Claude's work), a fallback builder, or a session started by a PM or an automation naming only a provider took the role's model, for example a Claude model id on Codex, and its effort. The role's effort is also left out on a provider without reasoning effort.
- **Resuming sessions after an upgrade or runner restart no longer breaks a session you resumed yourself.** CodeDen resumes the sessions a restart cut off one at a time. If you sent one of them a message or pressed Retry while it was still resuming the others (or a queued message reached it first), recovery still treated it as cut off: it closed the live turn and its approvals, tried to resume it a second time and could mark it failed. Recovery now asks the runner again what it hosts after each slow resume, and leaves alone any session that is running again or has a message on its way. A session that turns out to have a turn running is never marked failed.
- **Provider choices say which providers can run.** The hand-off dialog now starts on another provider that is signed in, and a provider that isn't installed or signed in shows why, the command that fixes it and a **Check again** button, instead of a **Continue** that starts a session that fails. While the brief is being written, the dialog says so. In a factory's Agents settings, the builder and reviewer provider lists mark providers that can't run, for example "Codex (not signed in)", and choosing one says what happens until it can (builders move to another provider; reviews follow the fallback you set).
- **Open PR asks the agent once.** Pressing **Open PR** again, or pressing it in the git bar and then in the Issue / PR tab or the Push toast, no longer sends the agent the same request two or three times. Once you've asked, all three show **PR requested** until the pull request is open. Hover over it to see whether the request is still queued behind the running turn or the agent is working on it. If the agent's turn ends without opening a PR, **Open PR** comes back. The state comes from the session's queue and transcript, so switching tabs or reloading the page keeps it.

### Security

- **Evidence checks the name a file is published under.** `attach_evidence` cleans up file names before publishing them, so `-id_rsa`, `notes.p!em`, `credentials.js!on` and `service/account.json` went out as `id_rsa`, `notes.pem`, `credentials.json` and `service-account.json`, past the secrets check. It and `share_to_chat` now also check every name in its published form, and refuse those files with `secret_file`, whether they are attached by path, renamed, or saved as an artifact and attached by id. `attach_evidence` also checks the final names, after `-2` tells repeated names apart. Ordinary files with odd names, `.env.example` and screenshots still attach. See [Security → Files](docs/security.md#files).
- **Agents can no longer switch off CodeDen's approvals by writing their own allow-list.** Cursor and Gemini CLI run what their allow-lists permit without asking, so a single `echo '{"permissions":{"allow":["Shell(*)"]}}' > .cursor/cli.json` used to turn approvals off for the session and, once merged, for every later Cursor session in the project. Creating or changing Cursor's `.cursor/cli.json` or `cli-config.json`, or Gemini CLI's `.gemini/settings.json`, `trustedFolders.json`, system settings or policy files, now asks at every permission level, Full included, for every edit and command CodeDen judges (Claude Code, OpenCode, Cursor and Gemini CLI calls, and what Codex asks to run outside its sandbox). This covers edit tools and shell writes (redirects, `tee`, `cp`, `mv`, `ln`, `dd of=`, `sed -i`, `git checkout`, PowerShell's `Set-Content`, `Out-File`, `Copy-Item` and inline `node -e` or `python -c` code). Codex's writes inside its own sandbox never reach CodeDen, so a Codex session can still write one; the warning below catches it when a Cursor or Gemini CLI session next starts there.
- **Gemini CLI starts under a CodeDen admin policy.** Its commands always ask, and its edits and MCP tools ask outside plan mode, whatever `tools.allowed`, trusted MCP servers or policy files allow, so CodeDen decides each one. Your own Gemini CLI deny rules still apply (`deny` policies in `~/.gemini/policies` or the project's `.gemini/policies`, `tools.exclude`, excluded MCP servers): CodeDen repeats your rules above its own, so what they deny stays denied at every level, and what they allow asks. Cursor has no option to ignore a project's allow-list, so it is guarded and reported instead.
- **A warning when a worktree already carries an allow-list.** A Cursor or Gemini CLI session whose worktree has allow rules in `.cursor/cli.json`, `.gemini/settings.json` or `.gemini/policies` names them in its first turn. In the software factory, the warning also goes on the item and into the inbox.
- **Handing off factory or triage work keeps its trust rules.** The brief of a hand-off used to relay the original session's first message, often a factory or triage brief quoting a GitHub issue, as CodeDen's own words, and clipped it at 4,000 characters, which could cut off the rule that issue text is data, not instructions. ### Security

- **Agents can no longer read CodeDen's own tokens without asking.** Reading or changing the install token, the runner's lock file or the network access store in `~/.codeden` now asks at every permission level, Full included, and is refused for Read-only sessions, the orchestrator and PMs. The path can be written out or reached through `~`, `$CODEDEN_HOME`, a wildcard or the folder that holds the file, anywhere in a command. **Approve for session** covers these files only for the exact call you approved, in the same directory. Before, an agent at Auto could read the install token and use CodeDen's local API to approve its own requests. Codex still runs reads it considers safe, such as `cat`, inside its own sandbox without asking; see [Security](docs/security.md#permissions).
- **The PM can't start work on a stranger's issue unless you asked.** A triage run, a GitHub or factory notice, a wake-up or another agent's message can start a PM turn, and in that turn the PM reads issues anyone can write. In those turns CodeDen now refuses `start_session` for an issue whose author isn't trusted (not one of the project's trusted authors, not the account CodeDen uses on GitHub, no write access to the repository) and refuses `factory_admit_issue` outright. The PM puts the issue in your inbox instead ("Should I take this on?"). When you ask the PM in your own message, or ask the orchestrator and it passes your request on, the PM can still start work on any issue and let one into the factory.
- **Three more ways around the guard on CodeDen's own tokens are closed.** A search with its options packed together (`grep -ne. ~/.codeden/install-token`, `grep -fFILE …`, `rg -e. ~`), a PowerShell list of paths (`Get-Content $env:CODEDEN_HOME\install-token,…`) and a CodeDen data folder whose name has `[`, `*` or `?` in it (`CodeDen [dev]`) no longer slip past the check. Before, these read the install token, the runner's lock file or the network access store without asking, at any permission level, and a bracketed data folder switched the guard off even for plain reads and writes. They now ask at every level and are refused for Read-only sessions, the orchestrator and PMs.
- **Evidence can no longer publish secrets.** `attach_evidence` now refuses secrets files (`.env`, `.npmrc`, SSH keys, `*.pem`, ...) and CodeDen's own credential files, wherever they are and under any name: renamed, reached through a symlink, or saved as an artifact. `share_to_chat` refuses them too, so a secret can't be staged as an artifact and attached by id. Before, an agent could publish its worktree's `.env` to the repository's `codeden/evidence` branch in one tool call, with no approval at any level. `.env.example` and other templates still attach. See [Security → Files](docs/security.md#files).

Full now lets Codex step outside its sandbox the same way, asking only for writes outside the worktree.
- **The browser panel keeps working on macOS for very large panels.** Above about 2560×1600, the picture used to be scaled below the page's own size, and on macOS Chrome then stopped sending pictures and reported the wrong page size, which put clicks in the wrong place. The picture now never goes below the page's size.
- **Quitting the desktop app can no longer hang.** If CodeDen's background server got stuck while closing, the app waited for it forever and never quit. It now stops the server after a short wait (forcing it if needed), a failed step while quitting no longer leaves the app open, and a server left behind by a crashed app exits by itself.
- **Agents, PMs and the orchestrator stop asking about things they can decide.** They now pick sensible defaults for routine details (approach, naming, scope, provider and model), say what they assumed so you can override it, and keep working; the orchestrator no longer ends replies with a menu of choices. They still ask you before destructive or irreversible steps, spending money or credentials, outward-facing actions such as publishing, releases, deploys or messages to people, and changes to protected areas.
- **Agents commit in their own worktree without asking.** A session started by a PM or an automation opens its pull request when the work is done; in a session you started, the agent opens one when you ask and otherwise offers it as a suggested follow-up. A question at the end of an agent's last message now reaches its PM instead of being cut off.
- **Stop always stops.** A turn whose agent never answered the stop request could stay "Working" forever; it now ends within 10 seconds either way. Messages you sent into a Claude turn that the agent hadn't read yet are dropped with it, instead of starting a new turn right after you pressed Stop, and the transcript says they weren't delivered.
- **No more dead approvals after a crash.** When CodeDen's background runner was killed or crashed, approvals and questions from the agent's cut-off turn stayed open in the inbox and could keep the session "Waiting" or "Working" long after it resumed. They're now cancelled before the session continues; questions an agent asked with `ask_user` stay open, since they can still be answered.
- **Agents hear about failed setup commands.** When a worktree setup command from `.codeden/project.json` failed, the session started anyway and the agent ran into confusing errors without knowing why. Its first message now begins with the command that failed, its exit code and the end of its output.
- **You can see when Claude is retrying or compacting.** A Claude session that hit an overloaded or rate-limited API, or was compacting a long conversation, looked stuck while Claude Code recovered by itself. The transcript now shows "The API request failed (overloaded, 529); Claude Code retries in 12s (attempt 2 of 10)", updated as the attempts go up, and "Compacting the conversation…" until it reads "Context compacted" (or says why it failed).
- **New sessions start from the latest code.** In a GitHub project, a session's worktree was branched from your local default branch, even when it was days behind GitHub, so agents worked on old code and opened pull requests with conflicts. CodeDen now fetches first and branches from the default branch on GitHub when your local one is only behind; a local default branch with commits of your own is still used as it is, and offline it carries on with the local one. CodeDen's git also never opens a Git Credential Manager sign-in window in the background.
- **Archived sessions free their disk space on Windows.** A dev server an agent started through its shell kept running after the agent stopped, kept the worktree in use, and the worktree (often with a large `node_modules`) could never be removed, silently. CodeDen now ends what its agents left running in a worktree when the session stops and before the worktree is removed; your own editors and terminals are left alone. A removal that still fails appears in the inbox under **Worktrees not removed**, with **Try again**, and the desktop app now always keeps its server log in `~/.codeden/logs/desktop-server.log`.

- **Read-aloud speaks a TL;DR.** **Settings › Voice › What to read** chooses between **TL;DR** (the default: one or two sentences saying what was done and whether anything needs you, about 15 seconds at most) and **Full message** (the whole final message without code or Markdown, up to 5,000 characters). ### Changed

- **A tidier session header.** The model and permission level are shown only under the message box, no longer repeated at the top of a session.

### Fixed

- **Read-aloud no longer reads long reports when a summary can't be made.** If the utility model fails or is unavailable, CodeDen now reads the message's first sentence or two instead of up to 600 characters (or the whole report, when the request itself failed).   - the PM sees the limit at triage and splits big work, or accepts work that can't be split (an initial scaffold, a stack migration) as one change;
  - a PR that's still too large goes to the PM to split or allow, with no fix round, without counting towards pausing the loop, and without waiting on you.
- **Saving one factory setting no longer resets the others** to their defaults.

A worktree with uncommitted changes is still kept unless you choose **Remove anyway**, and the toast says when changes were discarded. If a file in the worktree is in use, the toast offers **Try again**, and the hourly cleanup retries archived sessions on its own. The branch and checkpoints stay.

### Fixed

- **A slow-starting runner is no longer killed and relaunched.** CodeDen used to give a new runner 20 seconds, then kill it and start another, forever on a machine where start-up takes longer (security software, a slow disk). ## [0.1.0] - first public release

The first public release of CodeDen, a local-first harness for coding agents. Install with `npx codeden`.

### Daily driver

- **Claude Code** through the Claude Agent SDK (using your installed `claude` and its login) and **Codex** through `codex app-server`, behind one normalized event model.
- Agent sessions in their own **git worktrees and branches**, with `.codeden/project.json` setup commands.
- A transcript with grouped tool calls, plans and todos, subagent threads, and approval and question cards answerable inline.
- **Autonomy levels**: Supervised, Auto with risky actions asking (the default) and Full autonomy, mapped onto each provider's native enforcement.
- **Turn checkpoints** in hidden git refs: per-turn and whole-session diffs and file restore.
- **Workbench**: file tree and editor, runner-owned terminals that survive server restarts, and a browser the agents drive and you can take over.
- **Agent configuration** editors for memory files, skills, subagents and MCP servers, written to each provider's native files with a diff preview and a backup.
- **Image generation** for every agent through one `generate_image` tool (Codex, Gemini, OpenAI Images).
- **Voice**: dictation with push-to-talk and read-aloud of final messages.
- **Follow-up prompt chips** when a turn completes.
- First-run setup that detects and reuses existing Claude Code, Codex, GitHub and git setups, and `codeden doctor`.

### Orchestration

- An **orchestrator** across projects and a read-only **project manager** per project, with status digests on every wake and typed notices.
- **Work keys and conflict detection** with wait, skip, join and force.
- One **inbox** for questions, approvals, PRs ready for review, failed runs, triage decisions and conflicts.
- **GitHub** issue, PR, check and review sync through `gh`, PRs that link their issue and session, and screenshots and test output on the `codeden/evidence` branch.
- **Usage and cost reports**: a per-turn ledger, reported versus estimated costs, API-equivalent cost for subscriptions, rate-limit windows, budgets and alerts, and CSV export.

### Automations

- A scheduler with cron, event and manual triggers, guards (overlap policy, concurrency, quiet hours, daily caps, catch-up), runs history and per-project switches. All off by default.
- Built-in templates: security audit, refactor sweep, dependency updates, UI review, test coverage gaps, issue triage and stale PR follow-up. Custom automations as Markdown files.
- Issue triage by the PM, with a "Should I take this on?" inbox decision.

### Autonomy modes (experimental)

- Project modes Manual, Assisted (the default), **Autopilot** and **Dark factory**.
- A `.codeden/VISION.md` editor with protected areas, the factory loop, merge checks with an independent cross-provider review, automatic squash merge and automatic revert, server-enforced limits, a per-project and global kill switch, the factory panel and a daily digest.
